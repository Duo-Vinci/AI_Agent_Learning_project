# 生产环境检查清单

## 概述

本文档提供了一个全面的生产环境上线前检查清单，帮助团队确保系统在发布前达到生产就绪状态。每个检查项都包含详细说明和验证方法。

---

## 1. 上线前检查清单

### 1.1 环境准备
- [ ] **生产环境已配置**
  - 说明：所有必需的基础设施和服务已部署
  - 验证：访问生产环境，确认所有组件可达
  
- [ ] **环境变量已设置**
  - 说明：所有必需的环境变量已在生产环境中正确配置
  - 验证：检查配置管理系统或运行 `env` 命令验证

- [ ] **依赖服务已就绪**
  - 说明：数据库、缓存、消息队列等依赖服务正常运行
  - 验证：运行健康检查脚本，确认所有依赖服务响应正常

- [ ] **域名和 SSL 证书已配置**
  - 说明：域名解析正确，SSL 证书有效且未过期
  - 验证：`curl -I https://your-domain.com`，检查证书有效期

### 1.2 发布准备
- [ ] **发布计划已制定**
  - 说明：明确发布时间、步骤、负责人和回滚方案
  - 验证：审查发布计划文档，获得团队确认

- [ ] **变更通知已发送**
  - 说明：通知相关方（用户、运维、客服等）即将发布
  - 验证：确认通知邮件或公告已发送

- [ ] **回滚方案已准备**
  - 说明：制定详细的回滚步骤和触发条件
  - 验证：审查回滚文档，确保团队了解回滚流程

## 2. 代码质量检查

### 2.1 代码审查
- [ ] **所有代码已通过 Code Review**
  - 说明：所有变更都经过至少一名团队成员审查
  - 验证：检查 Pull Request 状态，确认已获得批准

- [ ] **代码符合编码规范**
  - 说明：代码遵循团队约定的编码标准和风格指南
  - 验证：运行 linter 工具，如 `eslint`, `pylint`, `rubocop` 等
  ```bash
  npm run lint
  # 或
  flake8 .
  ```

- [ ] **没有注释掉的调试代码**
  - 说明：移除所有调试用的 console.log、print 等语句
  - 验证：搜索代码库中的调试语句
  ```bash
  grep -r "console.log" src/
  grep -r "print(" src/
  grep -r "TODO\|FIXME\|XXX" src/
  ```

### 2.2 测试覆盖
- [ ] **单元测试通过率 100%**
  - 说明：所有单元测试必须通过
  - 验证：运行单元测试套件
  ```bash
  npm test
  # 或
  pytest tests/
  ```

- [ ] **集成测试通过**
  - 说明：关键业务流程的集成测试全部通过
  - 验证：运行集成测试
  ```bash
  npm run test:integration
  ```

- [ ] **代码覆盖率达标**
  - 说明：测试覆盖率达到团队设定的最低标准（通常 ≥ 80%）
  - 验证：生成覆盖率报告
  ```bash
  npm run test:coverage
  # 查看覆盖率报告
  open coverage/index.html
  ```

- [ ] **端到端测试通过**
  - 说明：关键用户场景的 E2E 测试通过
  - 验证：运行 E2E 测试套件
  ```bash
  npm run test:e2e
  ```

### 2.3 代码质量分析
- [ ] **静态代码分析无严重问题**
  - 说明：SonarQube 或类似工具未报告严重问题
  - 验证：检查代码质量平台报告

- [ ] **没有安全漏洞**
  - 说明：依赖项扫描未发现已知安全漏洞
  - 验证：运行安全扫描
  ```bash
  npm audit
  # 或
  snyk test
  ```

## 3. 安全检查

### 3.1 认证与授权
- [ ] **身份验证机制已实现**
  - 说明：所有需要保护的端点都有适当的身份验证
  - 验证：尝试未授权访问保护资源，应返回 401/403

- [ ] **授权检查已实施**
  - 说明：实现基于角色的访问控制（RBAC）
  - 验证：使用不同角色的账户测试权限边界

- [ ] **会话管理安全**
  - 说明：使用安全的会话令牌，设置适当的过期时间
  - 验证：检查 Token 配置，测试会话超时行为

- [ ] **密码策略已配置**
  - 说明：强密码要求、密码哈希存储（bcrypt, argon2）
  - 验证：尝试创建弱密码，应被拒绝

### 3.2 数据安全
- [ ] **敏感数据已加密**
  - 说明：静态数据（数据库）和传输数据（HTTPS）都已加密
  - 验证：检查数据库字段加密，确认 HTTPS 强制启用

- [ ] **SQL 注入防护已实施**
  - 说明：使用参数化查询或 ORM，避免字符串拼接
  - 验证：代码审查，查找原始 SQL 拼接
  ```bash
  grep -r "query.*+.*" src/
  grep -r "execute.*format" src/
  ```

- [ ] **XSS 防护已实施**
  - 说明：输出转义，CSP 头部配置
  - 验证：检查 HTTP 响应头，测试 XSS 攻击向量
  ```bash
  curl -I https://your-domain.com | grep "Content-Security-Policy"
  ```

- [ ] **CSRF 防护已实施**
  - 说明：使用 CSRF Token 或 SameSite Cookie
  - 验证：检查表单提交和状态变更操作的 CSRF 保护

### 3.3 配置安全
- [ ] **敏感信息不在代码中**
  - 说明：API 密钥、密码等敏感信息使用环境变量或密钥管理服务
  - 验证：搜索代码库中的硬编码凭证
  ```bash
  grep -r "password.*=.*['\"]" src/
  grep -r "api_key.*=.*['\"]" src/
  grep -r "secret.*=.*['\"]" src/
  ```

- [ ] **错误信息不泄露敏感信息**
  - 说明：生产环境错误信息应通用化，不暴露堆栈跟踪
  - 验证：触发错误，检查返回的错误信息

- [ ] **安全头部已配置**
  - 说明：设置 HSTS, X-Frame-Options, X-Content-Type-Options 等
  - 验证：检查 HTTP 响应头
  ```bash
  curl -I https://your-domain.com
  ```

- [ ] **CORS 策略已正确配置**
  - 说明：限制允许的源，避免使用通配符 `*`
  - 验证：检查 CORS 配置，测试跨域请求

### 3.4 依赖安全
- [ ] **依赖项无已知漏洞**
  - 说明：所有依赖项更新至安全版本
  - 验证：运行安全审计
  ```bash
  npm audit fix
  pip-audit
  ```

- [ ] **使用最新稳定版本**
  - 说明：框架和关键库使用最新稳定版本
  - 验证：检查 package.json 或 requirements.txt

## 4. 性能检查

### 4.1 响应时间
- [ ] **API 响应时间符合 SLA**
  - 说明：关键 API 的 P95 响应时间 < 200ms，P99 < 500ms
  - 验证：运行性能测试，检查响应时间分布
  ```bash
  ab -n 1000 -c 10 https://your-domain.com/api/endpoint
  ```

- [ ] **页面加载时间优化**
  - 说明：首屏加载时间 < 2 秒
  - 验证：使用 Lighthouse 或 WebPageTest 测试

### 4.2 资源优化
- [ ] **静态资源已压缩**
  - 说明：JavaScript、CSS、图片等已压缩和优化
  - 验证：检查构建输出，确认压缩生效
  ```bash
  ls -lh dist/assets/
  ```

- [ ] **启用 Gzip/Brotli 压缩**
  - 说明：Web 服务器配置了内容压缩
  - 验证：检查响应头
  ```bash
  curl -H "Accept-Encoding: gzip" -I https://your-domain.com
  ```

- [ ] **CDN 已配置**
  - 说明：静态资源通过 CDN 分发
  - 验证：检查静态资源 URL，确认指向 CDN

- [ ] **缓存策略已实施**
  - 说明：适当的 HTTP 缓存头（Cache-Control, ETag）
  - 验证：检查响应头中的缓存指令

### 4.3 数据库性能
- [ ] **数据库查询已优化**
  - 说明：消除 N+1 查询，使用索引
  - 验证：启用查询日志，分析慢查询
  ```sql
  SHOW PROCESSLIST;
  EXPLAIN SELECT ...;
  ```

- [ ] **数据库索引已创建**
  - 说明：常用查询字段已建立索引
  - 验证：检查数据库索引定义
  ```sql
  SHOW INDEX FROM table_name;
  ```

- [ ] **连接池已配置**
  - 说明：数据库连接池大小合理（通常 10-50）
  - 验证：检查应用配置和数据库连接数

### 4.4 负载测试
- [ ] **压力测试已通过**
  - 说明：系统能承受预期流量的 2-3 倍
  - 验证：运行负载测试工具
  ```bash
  k6 run load-test.js
  # 或
  locust -f locustfile.py
  ```

- [ ] **资源使用合理**
  - 说明：CPU 使用率 < 70%，内存使用率 < 80%
  - 验证：在负载测试期间监控系统资源

## 使用指南

### 如何使用本检查清单

1. **发布前 1-2 周**：开始执行本检查清单，留出充足时间处理发现的问题
2. **团队协作**：将检查项分配给不同团队成员，明确责任人
3. **记录证据**：对每个检查项保留验证证据（截图、日志、测试报告等）
4. **持续改进**：根据每次发布的经验，调整和完善检查清单

### 优先级说明

- **P0（必须）**：所有标记为"已实施"或"已配置"的项目都是必须项
- **P1（强烈推荐）**：与安全、性能、监控相关的检查项
- **P2（推荐）**：提升系统质量和可维护性的检查项
